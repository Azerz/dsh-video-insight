# dsh-video-insight 优化建议（对照 BibiGPT / NoteGPT / 通义听悟 / Eightify 等）

> 版本基线：v0.4.8（面板：左栏播放器 + 追问，右栏 总结 / 章节 / 原文 / 思维导图；RAG 追问、本地 Whisper/SenseVoice 转写、OCR + 视觉模型画面理解、按视频缓存、20 条历史、`video_digest` / `video` 两个全局工具）。
> 结论先说：**能力密度已经不输同类产品**（尤其"本地转写不出机 + 画面理解 + 播放器联动 + agent 工具"这几条它们大多没有），真正的差距在**"产出物的落点"**（导出/笔记/知识库）、**"读长内容的效率"**（翻译、跟随播放、关键画面）和**"批量/检索"**。

## 二、功能建议（按优先级）

### P0｜不做会一直"看完就走"的两件事

**1. 导出 / 沉淀：把面板里的结果变成文件**
- 现状：总结、章节、原文、导图、对话只在面板 + `~/.dsh/video-analyses/` 缓存里，想带走只能手动复制。
- 建议：右上角加「导出」菜单：
  - `复制 Markdown`（总结 + 章节 + 原文带时间戳 + 导图大纲 + 追问记录，一份完整笔记）
  - `保存为 .md`（host 写文件：`~/Desktop/` 默认，可配置目录；复用现有 `runProcess`/`writeFile` 思路，不引依赖）
  - `复制到剪贴板` 两种格式（纯文本 / Markdown）
  - 预留「发送到 Obsidian 库 / Notion」：Obsidian 只是"写到指定目录 + frontmatter"，可以纯本地实现；Notion 需要 token，做成可选设置。
- 成本：中（host 一个 `POST /export` + 客户端菜单），价值最高——BibiGPT/NoteGPT 都把"落到笔记"当卖点。

**2. 双语字幕 + 跟随播放**
- 现状：原文页签只有单语种字幕；播放器在左栏，读原文时不知道读到哪。
- 建议：
  - 原文页签加「翻译」按钮：把每段字幕批量翻译成目标语言（设置里选 中文/English/跟随总结语言），显示为「原文 + 译文」双行；复用现有 `/analyze` 的流式管线（可新开 `POST /translate`，按段批量、带缓存）。
  - 「跟随播放」开关：播放时按 `currentTime` 高亮当前句并自动滚动，点击仍可 seek；播放器通过 `postMessage` 上报时间（外壳已经能拿 `getCurrentTime`，加个 `timeupdate` 广播即可）。
- 成本：中；直接对标 BibiGPT 的"字幕翻译"与通义听悟的"实时字幕"。

### P1｜把"能分析"升级成"能复习"

**3. 关键画面（PPT / 代码 / 图表）页签**
- 现状：OCR / 视觉模型只在"没字幕/没声音"时兜底，平时有字幕就不会抽帧，视频里的 PPT、代码、图表全丢。
- 建议：新增「画面」页签 = 稀疏抽帧（默认每 20–30s 一帧，只抽变化大的帧）+ 缩略图 + 每帧一句描述（视觉模型，可选）+ 点击 seek。技术上是把 `captureFrames` / `describeFrames` 从"兜底"改成"按需产物"，缓存进 `video-analyses`。
- 成本：中（复用现有模块），差异化明显（对标通义听悟 PPT 抽取、Ai好记 图文笔记）。

**4. 片段收藏 + 高光笔记**
- 现状：时间戳能跳，但"这段值得记"没有任何落点。
- 建议：原文/总结里每段右侧一个「收藏」星标 → 生成"高光片段"列表（带 `[mm:ss]` 与一句话理由）；支持「复制带 `t=` 的链接」（YouTube `&t=90`、B 站 `?t=90`）。这是 BibiGPT"AI 高光笔记"的最小实现。
- 成本：低（纯客户端 + 缓存字段），但用起来很爽。

**5. 思维导图节点 ↔ 视频时间对齐**
- 现状：导图纯文本结构，节点点了只折叠，不跳转。
- 建议：让 `/mindmap` 的每个节点带上 `seconds`（prompt 里要求"该观点最早出现的时间点"），节点卡片显示 `00:32`，点击 seek；hover 高亮对应章节。
- 成本：低（host prompt + 字段 + 客户端一行 onClick）。

**6. 输出语言 / 语气可选**
- 现状：总结永远跟着视频原语言走（中文视频中文总结，英文视频英文总结），对"看外文资料"的人不够。
- 建议：设置里加「总结语言（跟随原片 / 简体中文 / English）」与「详细程度（速览 / 标准 / 精读）」，写进 `SUMMARY_SYSTEM` 与 maxTokens。
- 成本：低。

**7. 历史升级：搜索 / 收藏 / 标签 / 导出全部**
- 现状：20 条、按时间倒序、只能删。
- 建议：历史页加搜索框（标题/作者）、「收藏置顶」、按平台过滤、`导出全部为 Markdown`；上限从 20 提到 100（host 改一个常量 + 分页即可）。
- 成本：低。

### P2｜中期：从"单视频工具"变"视频知识库"

**8. 合集 / 播放列表批量分析**
- 对标 BibiGPT 的"合集归纳总结"：粘贴 YouTube playlist / B 站合集 / UP 主主页 → 队列逐个解析（串行，避免风控）→ 生成一个跨视频的「合集总览」（共同主题、分歧点、观看顺序建议）。
- 成本：高（host 队列 + 前端进度 + 汇总 prompt），但这是"看系列课程"的真实场景。

**9. 跨视频问答（知识库 RAG）**
- 现在 RAG 只在一个视频的转写稿里检索。把缓存里的所有 `video-analyses` 建成一个索引（BM25 已经写好，扩成多文档即可），问题先在全部视频里召回 → 回答里标注「来自《视频A》[12:30]」。
- 成本：中；对标 BibiGPT/Ai好记 的"知识库联合问答"。

**10. 复习产物：闪卡 / 测验 / 播客化**
- 用现有 LLM 生成「问答闪卡」页签（可导出 Anki CSV）、「3 道自测题」；播客化成本高（要 TTS），可后置。
- 成本：低-中；对标 NoteGPT 闪卡、BibiGPT 播客 / 闪记卡。

**11. 本地文件 / 网盘文件输入**
- 现在只吃链接。加「本地文件」入口（拖入 mp4/mp3/m4a → host 走 ffmpeg + whisper），对"录屏、网课下载、会议录音"非常实用。DSH 有 attachments 服务，桌面端可直接读路径。
- 成本：中（主要是文件选择 UI 与路径校验）。

## 三、UI 建议

### P0｜让阅读更顺

**1. 原文「跟随播放」+ 当前句高亮**（见功能建议 2）
- 左栏播放、右栏读原文是最常见的组合，现在两边是断开的。做一次 `postMessage({type:'dsh-video:time', seconds})` 广播即可。

**2. 章节列表「当前章节」高亮 + 章节缩略图**
- 播放到哪一章就高亮哪一张卡片，卡片左侧加 16:9 小缩略图（用 `i.ytimg.com/vi/<id>/mqdefault.jpg` 或 B 站封面裁切，零成本）。
- 成本：低；对标 YouTube 原生章节的观感。

**3. 分析过程可视化**
- 现在只有一行 phase 文案。建议顶部换成 4 段 stepper：解析 → 字幕/转写 → 检索/生成 → 完成，出错时停在失败段并给「重试 / 换模型 / 用本地转写」三个按钮。
- 成本：低。

### P1｜信息密度与操作效率

**4. 摘要区加「一句话结论卡」与「速览/精读」切换**
- 面板顶部固定一张卡：标题 + 一句话结论 + 时长/平台/观看建议（值得看 / 可跳过 / 只看 3–5 分钟）；下面正文默认「速览」（要点列表），切「精读」才显示完整六段。
- 成本：低（prompt 已经能产出，UI 折叠即可）。

**5. 播放器增强：画中画 / 浮窗、倍速、快捷键**
- 长总结阅读时把播放器缩成右下角浮窗（`position: sticky` 或小窗），不占左栏高度；
- 快捷键：`Space` 播放/暂停、`J/K` ±5s、`[` `]` 倍速、`S` 收藏当前片段、`Cmd/Ctrl+Enter` 发送追问。
- 成本：中（浮窗用 CSS + 现有 iframe 即可，真正的 PiP 受跨域限制，做"浮窗"而非原生 PiP）。

**6. 思维导图：缩放到适配 + 节点内搜索 + 导出 SVG/PNG**
- 现在缩放会随切换重置、长图要手动拖；加「适应宽度」、节点搜索定位、`导出 PNG`（客户端把 SVG 序列化即可）。
- 成本：低-中。

**7. 原文：虚拟滚动 + 搜索命中高亮 + 跳转**
- 一小时的视频有 300–500 段，现在全量渲染；加虚拟滚动与搜索命中定位（现在只有过滤）。
- 成本：中。

### P2｜观感与适配

**8. 亮/暗之外的阅读设置**：字号 12/14/16、行距、专注模式（隐藏左栏，全宽读）、高对比。
**9. 窄屏 / 移动形态**：已经是单列堆叠，可加底部 tab（总结/章节/原文/导图/追问）与"摘要折叠到一条"。
**10. 空态与引导**：首页已经很干净；可在输入框下加一行「支持：YouTube / B 站 / 短链」小字，和历史并排的"示例链接"（点击即解析，不写死卡片）。
**11. 国际化**：`locale/en.json` 已有，但面板文案是硬编码中文；如果打算发到英文市场，客户端文案抽到 locale 文件。

## 四、操作 / 工作流建议

**1. 粘贴即解析**
现在要粘贴 + 回车/点按钮。建议：输入框聚焦时 `paste` 事件检测到合法链接就直接提交（或显示"检测到链接，回车解析"提示），少一步。

**2. 从"读"到"问"的桥**
选中原文任意一段 → 右键/悬浮出现「就这段追问」「收藏片段」「复制带时间戳的引用」。现在追问只能整篇问，缺少"针对某句话问"的能力（RAG 已支持检索，把选中段作为 query 前缀即可）。

**3. 失败即给解法**
ASR/OCR/视觉失败的错误码已经有了，但文案只说"失败"。建议每个错误码配一个可点击动作：复制 `brew install ...`、打开设置填 Cookie、切引擎、降低 maxSeconds。用户少查文档。

**4. 凭证状态可视化**
设置里显示 B 站 Cookie 的"已保存 / 可能已过期（上次校验时间）"，并在解析失败时提示"Cookie 可能过期，去更新"。

**5. 缓存可见可控**
历史行显示"已缓存 · 3 小时前"，点开秒出；设置里加「清空全部缓存 / 只保留最近 N 个」；`~/.dsh/video-analyses` 体积可见（现在用户不知道占多少空间）。

**6. 与 DSH 会话打通**
- 面板加「把这份笔记发到当前会话」按钮：把 Markdown 作为消息发回会话，方便直接接着写报告/改公众号稿。
- 反向：会话里 `video_digest` 已经能用；可以再加一个 `video_notes`（导出完整笔记）和「合集批量」参数。
- 这条是**我们这个形态独有的优势**（BibiGPT 要 MCP 才勉强做到），值得做成显眼按钮。

**7. 一键分享**
生成一个只读快照（本地面板数据 → 一个自包含 HTML 或 Markdown），DSH 有文件发送能力的话可以直接发出去。比"截图"专业得多。

**8. 队列化批量**
输入框支持一次粘贴多行链接 → 变成任务队列（串行执行、显示进度、全部完成后汇总），替代手动一条条来。

## 六、要放大的三个差异点（对外表达）

1. **本地优先**：音频不出本机、转写/OCR/画面理解都在本地或你自己的模型上完成——同类都是云端 ASR + 云端总结。可以把"隐私模式"做成一个开关和一句显眼的说明。
2. **自带模型、免 API key**：用 DSH profile 里已有的模型，不改配置、不买额度。
3. **Agent 可达**：`video_digest` 让 QQ / 任意会话直接总结链接；未来"把笔记发回会话"能形成"看 → 读 → 写"的闭环。

> 备注：以上建议里 1–7 都不需要新运行时依赖（host 只用 Node 内置模块，客户端仍是单文件），符合当前插件"零构建、纯单文件 client"的约束；8–9 需要自建索引/队列，可以作为一个大版本再做。
